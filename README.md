# שיח — MVP מקומי לסימולציות ניהוליות

„שיח” היא סביבת הדגמה מקומית לבניית סימולציות שיחה להכשרת מנהלים ועובדים. מנחה יכול ליצור תרחיש ודמות, להכין תדריך למשתתף, לפרסם קישור ייחודי, להציג QR ולצפות בניסיונות ובדוחות מדומים.

ברירת המחדל נשארה demo מקומי, אך היישום כולל כעת Supabase Auth למנחים ושכבת נתונים ניתנת להחלפה בין `LocalSimulationRepository` לבין `SupabaseSimulationRepository`. אין עדיין הקלטת קול אמיתית או חיבור ElevenLabs.

## שני ממשקים נפרדים

- **ממשק המנחים** נמצא תחת `/admin`. הוא כולל את הדשבורד, אשף העריכה, ההגדרות הפנימיות, השיתוף והתוצאות.
- **ממשק המשתתפים** נמצא תחת `/simulation/:publicToken`. הוא כולל רק את התדריך המותר, פרטי המשתתף שנבחרו, השיחה המדומה ומסך הסיום. אין בו קישורים לממשק המנחים, תנאי הצלחה, מידע סודי או מדדים פנימיים.

הקוד אינו מעביר את אובייקט הסימולציה המלא למסכי המשתתף. השירות `participantSimulationService` יוצר תצוגה מצומצמת מסוג `ParticipantSimulationView`.

## התקנה והפעלה

נדרש Node.js ו־pnpm. לאחר פתיחת התיקייה בחלון פקודות:

```bash
pnpm install
pnpm dev
```

לאחר שהפקודה השנייה פועלת, פותחים בדפדפן:

```text
http://localhost:5173/admin
```

משאירים את חלון הפקודות פתוח כל עוד משתמשים במערכת. לעצירת המערכת לוחצים בחלון הפקודות על `Ctrl+C`.

אפשר לבדוק גרסת ייצור ובדיקות אוטומטיות באמצעות:

```bash
pnpm build
pnpm test
```

## יצירת סימולציה

1. פותחים את ממשק המנחים ולוחצים על **„יצירת סימולציה חדשה”**.
2. עוברים בין שמונת השלבים: פרטים כלליים, סיטואציה, דמות, התנהגות, תדריך, פרטי משתתף, מטרות וסיכום.
3. הטיוטה נשמרת אוטומטית. אפשר גם ללחוץ על **„שמירה כטיוטה”**.
4. לפני פרסום חובה להשלים שם סימולציה, תיאור סיטואציה, שם דמות ואת שדות החובה בתדריך.

## פרסום ובדיקת קישור המשתתף

1. בשלב **„סיכום ופרסום”** לוחצים על **„פרסום הסימולציה”**.
2. המערכת יוצרת token אקראי, כתובת ציבורית מקומית ו־QR.
3. במסך השיתוף אפשר להעתיק את הקישור, להוריד את ה־QR או ללחוץ על **„פתיחת קישור המשתתף”**.
4. במסך המשתתף ממלאים את השדות שנבחרו, מאשרים את התדריך ומתחילים.
5. כפתור המיקרופון מדמה מעבר בין „מקשיבה”, „חושבת” ו„מדברת”; הוא אינו מפעיל מיקרופון אמיתי.
6. לאחר סיום, הניסיון והדוח המדומה מופיעים במסך התוצאות של המנחה.

ביטול פרסום משבית מיד את הקישור. יצירת קישור חדש מבטלת את הקישור הקודם. token שגוי, קישור שבוטל, הוחלף או נמחק מקבלים הודעה ידידותית.

## מדוע הקישור המקומי לא זמין מחוץ למחשב

הכתובת `localhost` או `127.0.0.1` מצביעה על המחשב שבו המערכת פועלת. כל עוד לא פורסם backend אמיתי, הקישור אינו כתובת אינטרנט ציבורית. גם QR המכיל כתובת מקומית אינו הופך אותה לציבורית.

## בחירת ספק נתונים

הבחירה נעשית רק דרך `.env.local`:

```text
VITE_DATA_PROVIDER=local
```

`local` מפעיל את נתוני ההדגמה ב־`localStorage`. ‏`supabase` מפעיל סביבת עבודה משותפת לכל האדמינים המחוברים. כל אדמין יכול לראות, לערוך ולשכפל סימולציות שנוצרו בידי אדמינים אחרים; עותק חדש נרשם בבעלות המשתמש ששכפל אותו. אין fallback לנתוני demo.

`VITE_APP_ENV` מגדיר את סביבת הריצה: `development` (ברירת מחדל מקומית), `staging` או `production`. ב־`staging` וב־`production` היישום מסרב לעלות כאשר `VITE_DATA_PROVIDER=local`, ובמקום זאת מציג הודעת שגיאה חוסמת. כך אחסון ה־demo המקומי לעולם אינו יכול לשרת נתוני פיילוט אמיתיים.

## היכן הנתונים נשמרים במצב local

הסימולציות, הקישורים, המשתתפים, הניסיונות והדוחות נשמרים ב־`localStorage` של הדפדפן. רענון הדף שומר את הנתונים, אך ניקוי נתוני האתר בדפדפן ימחק אותם. הגישה לאחסון מרוכזת ב־`localSimulationRepository`; רכיבי React אינם ניגשים ל־`localStorage` ישירות.

בפתיחה הראשונה נטענות סימולציות לדוגמה ודוח לדוגמה כדי שאפשר יהיה להתנסות מיד. הזריעה מתבצעת רק כאשר האחסון ריק, ולכן דפדפן שכבר הריץ את המערכת לא יקבל תוכן חדש שנוסף ל־`demoData.ts`. כדי לראות תוכן חדש יש לנקות את נתוני האתר בדפדפן.

## הזנת סימולציות לסביבת Supabase

חשוב להבחין: `src/data/demoData.ts` הוא נתוני זריעה של ספק הנתונים המקומי **בלבד**. כאשר `VITE_DATA_PROVIDER=supabase` הקובץ אינו נקרא כלל, והסימולציות נשלפות מטבלת `public.simulations`. תוכן שנוסף ל־`demoData.ts` לא יופיע בסביבה מפורסמת.

שתי סימולציות הניהול ("משוב שנתי בלי הפתעות" ו"זה תמיד תלוי באחרים") מוגדרות פעם אחת ב־`demoData.ts`, ומשם נוצר סקריפט זריעה ל־Supabase:

```bash
pnpm seed:sql
```

הפקודה כותבת את `supabase/seeds/management_simulations.sql`. הקובץ נוצר אוטומטית ואין לערוך אותו ידנית — כך התוכן המקומי והתוכן בסביבת הפיילוט אינם יכולים להתפצל.

להזנה בפועל יש להריץ את תוכן הקובץ ב־SQL Editor של פרויקט ה־Supabase. הסקריפט:

- מוסיף רשומות בלבד (`INSERT`), ואינו מעדכן, מוחק או מקצר נתונים קיימים.
- מדלג על סימולציה שכבר קיימת לפי שם, ולכן הרצה חוזרת בטוחה.
- נכשל בהודעה ברורה אם עדיין אין פרופיל מנחה בבסיס הנתונים. יש להתחבר פעם אחת לממשק המנחים לפני ההרצה.
- מזין את שתי הסימולציות במצב `published` עם קישור שיתוף פעיל, כך שהן זמינות מיד למשתתפים שברשותם הקישור.

`owner_id` הוא זהות היוצר לצורכי תיעוד ואינו מגביל צפייה: מאז מיגרציית `202607190005` סביבת העבודה משותפת, וכל מנחה מחובר רואה ויכול לערוך את כל הסימולציות.

## מה עדיין מדומה

- השיחה הקולית, המיקרופון ומצבי ההקשבה/חשיבה/דיבור.
- התמלול, הסיכום, הציונים, החוזקות ונקודות השיפור.
- זהות המנחה והרשאות הגישה.
- הקישור הציבורי מחוץ למחשב.
- שמירה בענן, webhook וחיבור ל־AI.

## חיבור עתידי ל־ElevenLabs

הקובץ `elevenLabsService.ts` מכיל כעת placeholders עבור יצירת session, קבלת signed URL, התחלה, סיום ובדיקת סטטוס. בשלב הבא יש להוסיף backend מאובטח שיחזיק את `ELEVENLABS_API_KEY`, ייצור signed URL קצר־חיים ויחזיר אותו לדפדפן. אסור לשמור את מפתח השרת במשתנה `VITE_`, מפני שמשתנים כאלה נחשפים לדפדפן.

## Supabase ואימות מנחים

ה־`SimulationRepository` הוא חוזה האחסון המשותף. `SupabaseSimulationRepository` ממפה במפורש שדות מסד ב־snake_case למודל TypeScript ב־camelCase ומשתמש בטבלאות:

- `profiles`
- `simulations`
- `simulation_share_links`
- `participants`
- `simulation_sessions`
- `simulation_reports`

מסלולי `/admin` דורשים session מאומת. ה־RLS מאפשר לכל משתמש מחובר שאינו anonymous לעבוד במרחב האדמינים המשותף, בעוד `owner_id` נשמר כזהות היוצר לצורכי audit ועקביות. הקישור למשתתף קורא רק `ParticipantSimulationView` מצומצם דרך RPC. המיגרציות נשמרות מקומית תחת `supabase/migrations` ואינן מוחלות מרחוק אוטומטית.

בגרסה הנוכחית אין תפקיד נפרד במסד: כל חשבון Magic Link קבוע שהוזמן למערכת ואינו anonymous נחשב אדמין. אם יתווספו בעתיד משתמשים מחוברים שאינם אדמינים, יש להוסיף claim או טבלת memberships ולצמצם אליהם את מדיניות ה־RLS לפני צירופם.

קובץ `.env.example` מתעד את שמות המשתנים בלבד ואינו מכיל סודות אמיתיים.
